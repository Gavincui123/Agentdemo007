# CSDN 发布备忘：摘要 / 配图 / 注意事项

> 用途：本系列上传 CSDN 时的发布辅助。**「摘要」填 CSDN 发布对话框的摘要栏（不填会自动抓正文开头，会抓到「语言 / Language…」元信息块）**；正文里的「核心结论（TL;DR）」小节保留不动——它是给点进来的读者速读的，与摘要字段并存、互不替代。

## 一、各章摘要（直接粘贴到 CSDN 摘要栏）

- **第一章 · 设计理念与总体架构**
  一个电商客服 Agent 从立项到敢挂公网，架构上真正的载荷是几条"宪法级"契约：一进程即整站、15 步流水线以 @Order 定序、四态出口统一收口、状态唯一真相源、主链路线性而图只做固定子图、缓存不是真相源。本章给出七层全景，后面十一章都是这几条契约在某一次事故里的具体化。

- **第二章 · 提示词工程体系**
  提示词是变更最频繁、事故最集中的资产，治理方式是把它当代码：片段化存 Nacos 热更、四层拼接顺序逐位钉死、结构化分类提示词防模型漂移、兜底人格对齐"同一个客服"、画像注入位隔离。本章记录分段提示词体系从单模板翻车到装配契约落地的全过程。

- **第三章 · 模型网关与韧性治理**
  韧性不是加个 try-catch，是"分诊 → 重试 → 熔断 → 话术收口"的分层体系：异常先分诊再处置、同模型退避与换模型正交、熔断阈值按兜底质量分档（模型 5 次/工具 3 次/RAG 与画像 1 次）。附三个实测教训：并发丢失更新、间歇性成功掩盖故障、自纠正死循环。

- **第四章 · 会话记忆分层**
  会话记忆是四个生命周期、四种形态并存的分层系统：L1 token 预算窗口、L2 滚动摘要、L0 业务键注册表、L3 用户画像。一轮反思级 review 揪出注入位、读-改-写竞态、首字延迟敞口三个隐患，全部按"修根因不修表象"收口——记忆层失败必须不增加首字延迟、不污染指令位。

- **第五章 · 检索侧演进**
  检索模块三轮升级都是被真实缺陷逼出来的：搜不准订单号 → 稠密+稀疏双通道；旧政策冒充现行 → 时效治理；V1 客户搜到 V3 政策 → 知识分级 ABAC；无依据时自由发挥 → 拒答四层。红队毒片实验诚实归因：扫描器防注入，不防"像真的的错误"。

- **第六章 · 决策层、持久化与闸门硬化**
  把系统变成敢挂公网的作品集的四块工作：会话决策层升级为仲裁器、HITL 挂起-恢复落到三级持久化、统一访问闸口（口令 + IP 日额 + 评测端点封锁）、混合检索真 RAG 收尾。共享同一条设计纪律：不推翻已做好的东西，每层都是既有链路上的升级层，失败原样回退。

- **第七章 · 业务工具与售后工作流 DAG**
  当对话需要"真的办事"，怎么把 LLM 的不确定性关进确定性系统的笼子：动态 DAG 弯路回滚为固定子图、审批=事件（建单即返回、决议是状态变更）、高风险动作幂等键四态、mock 与 DB 同源种子对账。四个翻车与四个裁决，全部有源码落点。

- **第八章 · 全链路延迟与稳定性调优**
  全链路延迟从 80.5s 压到 6.1~11.9s 的实录：超时预算成链路地算（LLM 20s、嵌入 read 8s）、SSE 超时兜底让用户 100% 有响应、意图候选集硬隔离修复"开发票变转人工"的漂移、协作取消不再跑僵尸任务。规则短路径首字 2.1s。

- **第九章 · 评测体系**
  评测体系最容易死在"断言是空的"和"评测拖垮系统"：hollow eval 空转事故（字段全绿但从未对照）→ 强类型期望 + 对照逻辑；同步跑全量真 LLM 拖爆前端 → 异步作业 + 进度轮询；黄金集上 Nacos 实时拉取。"全绿"与"无缺陷"从此分开陈述。

- **第十章 · 前端与流式交互**
  前端是后端每条纪律在浏览器的镜像：SPA 直出后端 classpath 一进程即整站、fetch+ReadableStream 手撸 SSE（EventSource 不支持 POST）、reply_ready 权威终态整体替换流式半截、重试清场防缝合回答、三重前端闸口。264 行测试把 SSE 语义逐条钉死。

- **第十一章 · 可观测性与审计**
  可观测不是多打日志，是三条语义正交的信道：trace 贯穿全链路、audit append-only 异步落库、progress SSE 实时亮灯、metrics 只经门面打点。拒答、业务驳回、退役场景在统计口径上各归各位——监控里的每个数字都能被一句业务语言解释。

- **第十二章 · 部署交付实录**
  首次公网部署当天闭环炸出来的九个环境语义错位：profile 写死、Nacos 静默不加载、容器内 127.0.0.1 连不上中间件、MySQL CREATE 权限时序、打包不 clean 存量 chunk、nginx reload 假成功、XFF 伪造、反代缓冲 SSE、HIDS 探针认亲。九成不是代码问题，是环境与代码假设的错位。

## 三、注意事项

1. **编辑器**：用 CSDN 的 Markdown 编辑器（不是富文本）；粘贴前确认「核心结论（TL;DR）」标题行上下都是空行。
2. **图片**：正文里的 `![](assets/xxx.png)` 上传后需手动替换为 CSDN 图床链接。
3. **mermaid**：CSDN 原生支持，正文 mermaid 块已按旧版语法兼容处理（无单引号标签、无裸 #）；如再报渲染错误，把报错贴出来。
4. **标题锚点**：正文小节标题含 `;` 等符号的（如 核心结论（TL;DR）），如遇目录跳转异常可再简化。
